Three labs, worked step by step

Every screen below is the real workstation, recorded while doing the work. The tickets, people and IDs were generated for that run; yours will differ, so follow the method rather than the values.

  1. Onboard a nurse who starts todayJoiner, difficulty 1. PeopleHub, the birthright matrix, PowerShell, ADUC, ServiceDesk, Remote Desktop.
  2. A password reset that should not happenAuthentication, a trap. Identity verification against the HR record.
  3. An involuntary termination, right nowLeaver, P1. AD, Entra ID session revocation, Okta, Command Prompt.

Lab 1: onboard Mateo Silva, Registered Nurse, starting today

  1. Start the lab in IAM Coach

    Choose Joiner: New hire onboarding, variation Starts today, department Nursing, then Start this lab. The Mentor panel on the right answers questions about the lab at any point.

  2. Read the ticket

    ServiceDesk opens on RITM0010401. It names the worker, employee ID, title, manager and start date, and it is P2 because the person is waiting in the lobby. The ticket is the request, not the source of truth.

  3. Confirm the hire in PeopleHub

    PeopleHub is the system of record: Pending Hire, Registered Nurse, Nursing, reports to Iris Chandra, start date today. Everything you put in AD comes from here.

  4. Look up the birthright access

    Start, type Birthright, open the matrix. A Registered Nurse gets six groups: the role group, all-staff, ExpenseFlow, the nursing clinical share, VPN, and CareChart EHR. Nothing more: minimum necessary under the HIPAA policy.

  5. Build the account in PowerShell

    In Windows Terminal: New-ADUser in the Nursing OU with the HR attributes, a foreach over the birthright groups, a temporary password with -ChangePasswordAtLogon $true, Enable-ADAccount because the start date is today, then a delta sync so Entra ID gets the account. The warnings are the range coaching you on password hygiene.

  6. Check it in Active Directory Users and Computers

    Corp > Users > Nursing > Mateo Silva > Member Of shows exactly the six birthright groups, with Domain Users as the primary group.

  7. Write the work note and resolve the ticket

    The note says what you checked, what you changed and why, in words an auditor can follow. Resolve as Solved (Fulfilled).

  8. The mistake worth making once: testing with the user's temporary password

    Remote Desktop > Verify a sign-in as msilva with the temporary password works, and Windows asks for a new one, exactly as it should. But now IAM has chosen the nurse's working password and used up their first sign-in.

  9. The session works, and the check catches it

    Inside the session, whoami /groups shows the nursing groups. Then Check my work passes at 91% with one failure: Must change password at next logon: no. Verify a new account with net user msilva /domain or a test account, never by signing in as the person.

  10. Read the result and the debrief

    Every other check passes: naming standard, OU, HR attributes, exact birthright, enabled, synced, ticket resolved. The debrief explains why each matters; below it is an interview question to answer in your own words.

Lab 2: a password reset for Eli Moreau that should not happen

  1. Read what tier 1 collected

    An urgent caller "about to present to the board" wants the password read out over the phone, gives employee ID E100433, names Lucas Ferreira as manager, and asks to be called back on a new number.

  2. Compare it with PeopleHub

    The real Eli Moreau is E100410 and reports to Sam Rivera. Two of the three checks in the identity verification procedure fail, and the caller refused the callback on file. Urgency plus an executive pretext is the classic pattern.

  3. Change nothing, write it down, close it correctly

    No reset. The work note lists which checks failed; the ticket is resolved as Unable to Verify Identity and referred to Security.

  4. Passed at 100%

    The critical check is that the password was not reset. Resetting it, which the caller pushed hard for, fails the lab.

Lab 3: terminate Sofia Marin, effective immediately

  1. A confidential P1 from HR

    The person is in the meeting now and was on SharePoint minutes ago. Disabling AD alone will not stop the phone: cloud sessions and refresh tokens live on until they are revoked.

  2. Close every route in, in order

    Disable first, then Revoke-MgUserSignInSession in Microsoft Graph, remove every group except Domain Users with a pipeline, record the ticket in the description, move the account to Disabled Users (kept for 30 days, not deleted), and run a delta sync.

  3. Prove it from Command Prompt

    A second Terminal tab, net user smarin /domain | findstr /i "active expires memberships": Account active No, only Domain Users left.

  4. Okta: clear sessions and deactivate

    Okta keeps its own sessions. Clear them, then deactivate. The groups listed there refresh at the next AD import, which is why the session step cannot wait for it.

  5. Resolve and check: 100%

    Every route is closed: AD, Entra ID, Okta, the SCIM-provisioned apps, and the record is kept for retention.
